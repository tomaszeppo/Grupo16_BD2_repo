# Mapa de dependencias del Hito 10

Los valores se toman del `.env.example`, `app/config/settings.py`, `docker-compose.yml`, adaptadores y rutas existentes del Hito 10. Los hosts/puertos pueden cambiar según el entorno; antes de interpretar resultados, comparar con la configuración local efectiva sin publicar sus secretos.

| Producto | Módulo del Fixture | Proceso que conecta | Host y puerto usados por la aplicación | Protocolo / cliente | Contexto | Lectura mínima y endpoint de API |
|---|---|---|---|---|---|---|
| MongoDB | Equipos y jugadores | `MongoAdapter` en `app/adapters/mongo.py` | Notebook: `MONGO_HOST:MONGO_PORT` (por defecto `localhost:27017`); Docker API: `mongodb:27017` | MongoDB Wire Protocol, driver `pymongo` | Database `fixture2030`; colecciones `equipos`, `jugadores`; autenticación contra `admin` si `MONGO_USER` está configurado | `ping` + verificación de existencia de database/colección y `find_one` de `equipos`; `GET /equipos/ARG`, `GET /equipos/ARG/jugadores?limit=2`. ## Lectura de este mapa

- “Notebook” se refiere a la API lanzada con `bash scripts/iniciar_api.sh --local`. Los puertos son los publicados en el host; si se remapean, actualizar también las variables locales que use la API.
- “Docker API” se refiere al servicio `api` bajo el perfil Compose `api`. `docker-compose.yml` sobrescribe sus hosts con nombres de servicio y usa los puertos internos, no los puertos publicados en la notebook.
- La API mantiene drivers inicializados de forma perezosa. `GET /health` ejecuta `ping()` de los seis adaptadores y devuelve un estado individual por fuente. Las rutas representativas completan la prueba con una operación de lectura.
- Los scripts de conectividad nunca imprimen valores de password/token ni URI completas de conexión.
